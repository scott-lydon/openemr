Five steps from download to running

1

Download and verify

Click the download button above. In a terminal, verify the file integrity:

shasum -a 256 oe-module-clinical-copilot-latest.zip
# compare to oe-module-clinical-copilot-latest.zip.sha256
2

Unzip into your OpenEMR custom modules folder

On a typical install:

unzip oe-module-clinical-copilot-latest.zip \
  -d /var/www/openemr/interface/modules/custom_modules/

For Docker, mount or copy into the same path inside the OpenEMR container.

3

Register and install in the Module Manager

In OpenEMR, sign in as admin. Open Modules › Manage Modules. Find Clinical Co-Pilot in the Unregistered list. Click Register, then Install, then Enable.

The module's InstallListener creates a private settings table and seeds a JWT signing key. Nothing else is touched.

4

Paste the sidecar URL and license key

Open Administration › Globals › Clinical Co-Pilot in OpenEMR. Paste:

  • Sidecar URL — for the managed option: https://api.copilot.scott-lydon.dev
  • License key — the one in your welcome email after Stripe signup

Click Test connectivity. You should see auth_method: HS256_jwt and license_state: active.

5

Open any patient chart and click the button

The Co-Pilot button now appears on the patient summary. Click it. The first pairwise cross-check should return within ~5 seconds with citations into the chart.

Where does the license key come from?

When you click Start trial on the pricing page, Stripe Checkout collects your email and (for paid tiers) a card. The webhook handler in the sidecar materializes a row in the licenses table and emails you the key. Pre-launch (before the Stripe products are live) email us at relays.inanity.0n@icloud.com for a trial key.

License key vs. JWT signing key.

The license key gates whether the sidecar accepts requests from your install. The JWT signing key is a separate per-install secret that the module mints task tokens with. Both are managed in Administration › Globals › Clinical Co-Pilot. Never share either.

Self-host the sidecar (optional)

If you want the LLM call to run inside your VPC, use the self-host compose stack. Multi-arch images are published on every release tag.

cd /opt
git clone https://github.com/scott-lydon/openemr.git
cd openemr/clinical-copilot/deploy
cp .env.example .env  # set OPENAI_API_KEY, COPILOT_JWT_SIGNING_KEY, LICENSE_KEY
docker compose -f docker-compose.openemr-sidecar.yml up -d

Then set the Sidecar URL in OpenEMR Globals to http://localhost:8088 (or whatever host:port your sidecar exposes).

Full self-host guide: OPERATOR_GUIDE.md.

Common problems

Module shows up in Manage Modules but Install is greyed out

Usually a file permissions issue on interface/modules/custom_modules/oe-module-clinical-copilot/. The OpenEMR PHP process needs read access. On Linux, run chown -R www-data:www-data on the folder (replace www-data with whatever user PHP-FPM runs as on your install).

Test connectivity returns license_state: missing

The license key in OpenEMR Globals does not match a row in the sidecar's licenses table. Check that the Stripe webhook fired (the dashboard has an event log) and that your license key was copied without surrounding whitespace.

Test connectivity returns auth_method: anon

The sidecar accepted the request without a JWT, which means the module did not mint or send one. Check that the JWT signing key is set in OpenEMR Globals (Clinical Co-Pilot section) and not just blank. Re-running Install on the module regenerates it.

The Co-Pilot button does not appear on the patient summary

The render listener is wired to RenderEvent::EVENT_SECTION_LIST_RENDER_TOP and is only registered when the module is Enabled. Re-check that the module is Enabled in Manage Modules. Then check the OpenEMR PHP error log for any bootstrap errors:

tail -f /var/log/openemr/php-error.log
