Trust and security

What Clinical Co-Pilot does with Protected Health Information, who has access to it, and how every claim is auditable. Designed against the HIPAA Security Rule and the OCR audit protocol.

HIPAA-aligned OpenAI Enterprise BAA + Zero Data Retention Hash-chained audit log, 7-year retention Read-only against FHIR SOC 2 Type II in progress

Posture summary

Clinical Co-Pilot is a Business Associate under HIPAA. The sidecar transmits Protected Health Information (PHI) to the Large Language Model (LLM) for the diagnostic cross-check, with these guardrails:

  • No write-back by default. The cross-check and chart-error scan are read-only. Document ingest is opt-in and requires per-suggestion clinician confirmation.
  • No training on PHI. OpenAI Enterprise tier with Zero Data Retention is enabled; prompts and completions are not retained by OpenAI and are not used to train models.
  • No PHI to Cohere. The reranking step runs on de-identified candidate strings, not the raw chart.
  • Audit-first design. Every prompt, response, and citation is hash-chained and replayable.
  • Encryption at rest and in transit. TLS 1.2+ in transit. Audit log encrypted at rest. Backups encrypted with customer-rotatable keys for Enterprise tier.

Security controls

Authentication and authorization

Every sidecar request carries an HS256 task token minted by the OpenEMR module with a 5-minute lifetime. Token covers user ID, patient ID, and purpose-of-use. Sidecar verifies signature and freshness on every call.

Encryption

TLS 1.2+ in transit. Audit log encrypted at rest via PostgreSQL TDE (managed) or LUKS (self-host). Customer-rotatable keys for Enterprise tier.

Tamper-evident audit log

Every row hashes the previous row's hash + the new payload. Daily chain head writes to AWS S3 Object Lock with a 7-year retention policy. Tampering with the log is detectable.

Read-only FHIR

The sidecar holds a short-lived OAuth access token scoped to read on Patient, Condition, Observation, MedicationRequest, AllergyIntolerance, Encounter, Procedure, DocumentReference. No write scopes. No admin scopes.

Injection guards

Prompt injection guard rejects W2/W3-pattern foreign Patient/ references and instruction-shaped phrases in patient data. Per-session turn cap enforced by the chat router.

License gating

FastAPI dependency on every prompt endpoint resolves the license key against the licenses table. Subscriptions revoked by Stripe webhooks revoke the dependency on the next request.

Incident response

If a breach is detected:

  1. Investigation begins within 24 hours of detection.
  2. Customer notification within 60 days under HIPAA Breach Notification Rule.
  3. Audit log replay establishes the affected patient set and the access pattern.
  4. Post-incident report shared under NDA with affected customers.
